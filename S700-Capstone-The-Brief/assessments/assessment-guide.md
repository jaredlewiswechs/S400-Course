# Assessment Guide — S700 Capstone: The Brief

## Assessment Philosophy

S700 is assessed almost entirely through the capstone project. There are no unit quizzes, no isolated labs, and no separate writing assignments. Every piece of work feeds into the policy brief. Assessment tracks both the process (how the student worked) and the product (what they produced). GitHub commit history provides objective evidence of sustained effort and intellectual development.

## Grading Structure

| Component | Weight | Description |
|-----------|--------|-------------|
| Process Documentation | 15% | Research journal, GitHub commits, weekly check-ins |
| Methodology Review | 10% | Peer-reviewed methodology (Phases 2–3) |
| Draft Brief | 15% | Complete first draft with analysis (Phase 4) |
| Final Policy Brief | 35% | Publication-quality R Markdown report (3,000–5,000 words) |
| Panel Defense | 15% | Oral defense before external panel |
| Portfolio & Reflection | 10% | Course portfolio and reflective essay |

## Assessment by Phase

| Phase | Deliverables | Points |
|-------|-------------|--------|
| 1: Problem Scoping | Research Proposal, GitHub setup, literature review | 130 |

## Process Grade: GitHub Commit History

GitHub provides an objective measure of sustained work. The commit history is reviewed at each phase checkpoint.

| Phase | Minimum Commits | What Commits Should Show |
|-------|----------------|-------------------------|
| 1 | 5 | Proposal drafts, literature notes, data feasibility checks |
| 2 | 10 | Acquisition scripts, cleaning iterations, data dictionary |
| 3 | 15 | Analysis iterations, model exploration, visualization drafts |
| 4 | 20 | Writing drafts, revision cycles, figure updates |
| 5 | 5 | Presentation drafts, Q&A prep |
| 6 | 5 | Portfolio assembly, reflection, final revisions |
| **Total** | **60** | Evidence of sustained, thoughtful work |

### Commit Quality Rubric

| Grade | Description |
|-------|-------------|
| A | 60+ commits with descriptive messages; steady work across all phases; each commit represents meaningful progress |
| B | 45–59 commits; mostly descriptive; some periods of inactivity but catches up |
| C | 30–44 commits; many vague messages; bursts of activity before deadlines |
| D | <30 commits; most work done last-minute; commit history does not show sustained effort |

## Weekly Check-In Protocol

During Phases 2–4, students have weekly check-ins with the teacher (3–5 minutes each).

**Student prepares:**
- What I did this week.
- What I found.
- What I'm stuck on.
- What I plan to do next week.

**Teacher provides:**
- Is the student on track?
- Methodology guidance.
- Flag any risks (data problems, scope creep, analytical errors).

Check-ins are graded pass/fail: prepared and engaged = pass.

## Final Policy Brief Rubric (Expanded, 100 points)

This is the master rubric for the single most important deliverable of the entire S400–S700 sequence.

### Content (60 points)

| Criterion | Excellent (A) | Proficient (B) | Developing (C) | Beginning (D) | Points |
|-----------|---------------|-----------------|-----------------|----------------|--------|
| **Executive Summary** | Standalone summary; captures problem, finding, and recommendation in <300 words | Mostly complete | Vague or incomplete | Missing | 8 |
| **Background** | Well-researched; problem clearly defined; 3+ literature sources cited; establishes significance | Adequate context | Thin; few sources | Missing | 8 |
| **Data & Methods** | Clear, accessible description; all sources documented; limitations honest; reproducible | Mostly clear | Important gaps | Incomprehensible | 8 |
| **Finding 1** | Clear statement, strong evidence, correct statistics, well-integrated visualization | Good but minor issues | Present but weak evidence | Missing or incorrect | 8 |
| **Finding 2** | Same standard as Finding 1 | Good | Present but weak | Missing | 8 |
| **Finding 3+** | Additional findings, robustness checks, or depth of analysis beyond the minimum | Third finding present | Only 2 findings | Only 1 finding | 5 |
| **Discussion** | Thoughtful; addresses limitations, confounders, alternatives; connects to broader context | Addresses some limitations | Surface-level | Missing | 7 |
| **Recommendations** | 2+, specific, actionable, evidence-based, prioritized, connected to findings | Present but somewhat vague | Weak or disconnected | Missing | 8 |

### Statistical Rigor (20 points)

| Criterion | Excellent (A) | Proficient (B) | Developing (C) | Beginning (D) | Points |
|-----------|---------------|-----------------|-----------------|----------------|--------|
| **Test Selection** | All tests appropriate for the data type and question | Mostly appropriate | Some inappropriate | Wrong tests | 5 |
| **Execution** | All tests run correctly; output reported in full (statistic, df, p, CI) | Mostly correct | Significant errors | Incorrect | 5 |
| **Interpretation** | Every result interpreted in substantive terms; distinction between statistical and practical significance | Mostly interpreted | Some interpretation | Raw output only | 5 |
| **Robustness** | 2+ robustness checks; results discussed honestly | 1 check | Mentioned but not done | None | 5 |

### Technical Quality (20 points)

| Criterion | Excellent (A) | Proficient (B) | Developing (C) | Beginning (D) | Points |
|-----------|---------------|-----------------|-----------------|----------------|--------|
| **Visualizations** | 5+ polished figures; clear titles, labels, annotations; each advances the argument | 4 good figures | 3 figures with issues | <3 or poorly made | 6 |
| **Tables** | Publication-quality formatting (gt/kable); descriptive stats table + regression table | Tables present, minor issues | Some tables | No formatted tables | 4 |
| **Reproducibility** | Knits from scratch without errors; data dictionary present; all scripts in GitHub | Knits with minor issues | Knits but with problems | Does not knit | 5 |
| **Writing** | Analytical tone; smooth transitions; professional formatting; 3,000–5,000 words | Mostly professional | Uneven quality | Unprofessional | 5 |

## Accommodations and Differentiation

| Student Need | Accommodation |
|-------------|---------------|
| Extended time | Build buffer weeks into the timeline; allow Phase 4 to extend into Phase 5 prep |
| Anxiety about defense | Allow written Q&A responses in addition to (not instead of) oral defense; provide questions in advance |
| Struggling with statistics | Pair with a peer mentor; provide additional worked examples; allow simpler models (t-test instead of regression) with strong interpretation |
| Advanced students | Encourage more sophisticated methods (bootstrap CI, logistic regression, spatial regression); connect to college-level research |
| ELL students | Allow outline and key terms in home language; focus defense rubric on content over fluency |
| Students without home internet | Ensure all GitHub operations can be done during class; provide offline R Markdown knitting |
| Students who miss class | GitHub commit history provides objective evidence of work done at home; weekly check-ins can be rescheduled |
